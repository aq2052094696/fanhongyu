环境准备

安装 Node.js 24 以上版本，尽量安装 cnpm 加速依赖安装

  • 到 Node.js 官网下载 24 及以上版本安装包，一路默认完成安装。
  • 打开命令行验证：node -v，确认版本号不低于 24。
  • 安装 cnpm 镜像工具：npm i -g cnpm，之后安装依赖优先用它（失败或超时再改用 npm）。
  • 准备好代码编辑器（如 Trae / VS Code），并确认 Git 可用。
本阶段只做一次，后面所有项目都可以复用这套环境。
1

创建项目文件夹，设立规则 AGENTS.md 关键

先定规矩，再让 AI 干活；AGENTS.md 是整个项目的"宪法"

  • 新建一个项目文件夹（建议英文命名，避免中文路径），用编辑器打开。
  • 在根目录创建 AGENTS.md，把下方的"全栈开发提示词"完整写入。
  • 按自己的情况修改给定提示词：把姓名、学号改为本人信息（樊宏宇 / 24001010618），也可自行补充要求。
  • 以后每次向 AI 发出开发指令，AI 都会依据这个文件里的规则生成代码。
AGENTS.md · 全栈开发提示词（点击右侧复制）
在当前项目根目录创建 AGENTS.md，写入以下规则。

## 项目结构与技术栈
- 前端：frontend/ 目录
  - 原生 HTML、CSS、JavaScript，禁止使用任何第三方库、框架、CDN 链接
  - 目录结构：frontend/ 下建 css/、js/、fonts/、images/ 子目录；
    fonts/ 存放 iconfont 图标文件（如果有）
- 后端：backend/ 目录，Node.js + Express，RESTful+MVC 风格，
  所有接口以 /api/ 为前缀，端口固定为 8618，
  并以 express.static 托管 frontend/ 目录
  后端支持所有跨域访问。
- 后端依赖安装：优先 cnpm i 包名；失败或超时则使用 npm i 包名
- 数据库：MySQL （用户名 root、密码：123456）：
- 数据库凭据写入 backend/.env（变量名：DB_USER、DB_PASSWORD、
  DB_HOST、DB_NAME），不得出现在代码或 AGENTS.md 中；
  .env 同时加入 .gitignore
- 根据后端的要求自行建立和修改数据库表，每张表建立后，插入至少 8 条有真实业务意义的测试数据

## 命名与注释
- CSS 类名、JS 变量名、JS 函数名、数据库表名（及字段相关命名）
  一律以 Fanhy_ 开头
- 每个文件头部包含注释块：
  姓名：樊宏宇 | 学号：24001010618 | 时间：yyyy-mm-dd | 大模型：{本次使用的大模型名称}

## 记录文件（一律追加写入，禁止覆盖已有内容）
- Fanhy_prompt.md（项目根目录）：每次向 AI 发出开发指令后，
  追加记录：时间 | 提示词全文 | 大模型名称
- backend/Fanhy_interface.md：每次创建或修改接口后，追加：
  接口路径 | HTTP 方法 | 请求参数（含示例）|
  响应格式（含 JSON 示例）| 修改时间
- backend/Fanhy_database.md：每次建表、改表或插入数据后，
  按执行顺序追加对应 SQL 语句（含测试数据的 INSERT），
  要求仅凭此文件即可在新机器上完整重建数据库
- 统一 JSON 响应格式：{ "code": 0, "msg": "提示信息", "data": {...} }，
  code=0 表示成功，非 0 表示失败

## 前端约定
- 服务器返回的数据和错误信息输出到浏览器控制台（console.log / console.error）；
- 新建 HTML 页面后，在 frontend/index.html 中追加超链接入口；
  文件名包含 detail 的页面除外
提示：规则全文也整理在下方"核心规则解读"一栏，便于对照理解每一条的作用。
2

初始化项目 关键

把初始化提示词交给 AI，自动完成建库、建目录、装依赖、做首页

  • 把下方"初始化提示词"整段发给 AI 执行，等待它自动完成初始化。
  • 检查是否已执行 git init，生成 .gitignore（排除 node_modules、.env）并完成首次提交。
  • 检查是否已按 AGENTS.md 建好 frontend/、backend/ 前后端目录骨架，并安装好依赖。
  • 检查前端首页 index.html：应包含姓名、学号、项目名称、项目类别，以及所有已完成 HTML 页面的超链接；带 canvas 背景动画，主体为页面导航，整体美观。
  • 检查根目录是否已生成 readme.md，内容包括学号、姓名。
初始化提示词（点击右侧复制）
请初始化本项目：
1、 git init + .gitignore（排除 node_modules、.env）+ 首次提交
2、按 AGENTS.md 规则创建前后端目录骨架、安装依赖、

3

运行和查看项目

创建后台运行的 bat 文件，一键启动并打开首页

  • 在根目录新建一个 .bat 批处理文件，用于启动后端服务并保持窗口不关闭。
  • 双击该 bat 文件运行；后端按规则以 express.static 托管 frontend 目录，并监听 8618 端口。
  • 浏览器访问 http://localhost:8618，查看首页效果：canvas 动画、导航链接、姓名学号等信息是否正常。
  • 后续每新增一个页面，都要回到首页确认链接入口已追加。
bat 文件示例（入口文件名按后端实际修改）
@echo off
cd /d %~dp0\backend
node app.js
pause
4

测试数据库连接 MySQL 需要 / SQLite 可跳过

创建 database.html，输入用户名密码连接数据库并给出提示

  • 确认 MySQL 服务已启动，并准备好可连接的用户名与密码（规则中约定 root / 123456）。
  • 创建 database.html 页面：提供用户名、密码输入框和"连接数据库"按钮。
  • 点击连接后调用后端 /api/ 接口发起测试，成功和失败都要有明确提示。
  • 默认用户名 root、密码 root（测试页默认值；实际连接需与 MySQL 或 backend/.env 中的配置一致）。
  • 按"前端约定"，把接口返回的数据与错误信息用 console.log / console.error 输出到控制台，方便排错。
  • 在 backend/Fanhy_interface.md 追加该测试接口的记录。
注意：初始化提示词中数据库测试页默认密码写的是 root，而 AGENTS.md 中 MySQL 密码约定为 123456。请以本机实际密码或 .env 配置为准，两处保持一致即可。
5

完成科技新闻列表页面 核心功能

数据存入数据库表，网页显示后端接口链接和数据内容

  • 让 AI 根据后端需要建立科技新闻表，并插入至少 8 条有真实业务意义的测试数据。
  • 后端按 RESTful + MVC 风格创建新闻接口，统一以 /api/ 开头，返回统一 JSON 格式 { code, msg, data }。
  • 前端新建新闻列表页面，用 fetch / AJAX 调用接口获取数据在页面中渲染。
  • 页面上要显示后端接口链接和接口返回的数据内容。
  • 在 frontend/index.html 中追加该页面的超链接入口。
  • 追加三份记录：Fanhy_prompt.md 记录本次提示词、Fanhy_interface.md 记录接口、Fanhy_database.md 记录建表与 INSERT 的 SQL。
提示：数据库表字段可参考"标题、摘要、来源、发布时间、图片地址"等，命名一律以 Fanhy_ 开头。
6

完成图文列表 核心功能

新建一张表，图片可用网络图片或自行创建，同样显示接口与数据

  • 创建新表存放图文数据（如标题、图片地址、简介），并插入至少 8 条测试数据。
  • 图片可直接使用网络图片链接，也可以自己创建后放入 frontend/images/。
  • 后端新增对应 /api/ 接口，前端新建图文列表页面调用接口渲染。
  • 页面上同样要显示后端接口链接和数据内容。
  • 在 frontend/index.html 追加超链接入口，并追加三份记录文件。
  • 最后回到首页整体检查：链接齐全、样式美观、控制台无报错，即可完成验收。
